Guide

You decide how much to trust.

T.R.I.S.T.A.N. asks before it acts by default. Here is exactly what each mode does and how little an Always-allow rule remembers.

Three trust levels

Default

ASK

T.R.I.S.T.A.N. asks before each action. You approve or deny in the window or from the notch.

Middle

AUTO

Routine actions run without asking. Risky ones are blocked or still ask.

Careful

YOLO

All permission checks are skipped. It needs an explicit confirmation and shows a red badge.

What Auto means for each provider
ProviderIn Auto mode
Claude CodeIts own safety classifier decides.
Bedrock, Azure, OllamaWrites inside the working folder and plain commands run; anything else asks.
CopilotA short allow-list of file writes and routine commands; everything else is refused.
iPhone standaloneWrites inside the folder go ahead. There is no shell, and no Yolo.

Yolo is exactly as risky as it sounds. Do not use it in a folder you cannot afford to lose.

Always allow, kept narrow

The approval prompt has an ALWAYS ALLOW button that remembers a rule so you are not asked again. Rules are saved between launches and listed in Configuration, where you can remove them one by one or clear them all. T.R.I.S.T.A.N. only offers it where generalising is reasonably safe:

What a rule remembers
ActionRule it remembers
Edit, Write, MultiEdit, NotebookEditThat tool, for files inside the working folder only.
BashThe program name only, for example npm or touch.

It is not offered for shell commands that chain or redirect (;, &&, |, >, <, backticks, $(…)), for risky programs (rm, sudo, dd, chmod, mv, curl, sh, ssh and similar), or for any other tool. Those always ask.

Allowing a program such as npm lets it run any arguments you did not see, so treat the rule as trust in that program.

How an approval travels

In Ask mode T.R.I.S.T.A.N. starts Claude Code with a permission-prompt tool that points at its own binary, run as a tiny helper (Tristan --mcp-permission <socket>). When Claude Code needs permission for a tool call:

  1. It calls the approve tool on that helper.
  2. The helper forwards the request over a private Unix socket, in a temporary folder only you can read, to the running app.
  3. The app shows the action in the window or the notch and waits for you.
  4. Your answer goes back as allow or deny.

Auto and Yolo skip this bridge and pass Claude Code’s own auto or bypassPermissions mode instead. For the model-only providers (Bedrock, Azure, Ollama) the shared agent loop asks you itself before each tool call; the file tools are confined to the working folder.

Several sessions, one set of rules

Each tab is its own session with its own provider, folder, log and approvals. The approval mode and the Always-allow rules are shared by all of them. A session that needs you in the background raises an amber banner, a sound, a spoken line and a notification, and the notch can show and answer it. Starting a session in a folder another session is already working in warns you that edits may collide.
