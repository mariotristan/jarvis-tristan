Guide

Your Mac, your model.

Run T.R.I.S.T.A.N. on a local model with Ollama. One script sets it up, and nothing leaves the machine.

Quick start

scripts/setup-ollama.sh                 # installs Ollama if needed, pulls llama3.1
scripts/setup-ollama.sh qwen2.5-coder   # or pull a different model by name

Then open T.R.I.S.T.A.N., pick OLLAMA along the bottom and give it a task. In Configuration > OLLAMA you can see the installed models, click one to choose it and press REFRESH to rescan. Leave the model blank to use the first installed one.

Nothing is sent over the internet while you work. The only download is the model itself, from Ollama’s registry, when you pull it.

On Windows

For the tristan terminal command, scripts\setup-ollama.ps1 checks for Ollama, starts it, pulls the model, checks it answers and can use tools, and sets it with tristan config set ollama.model. It never installs Ollama by itself: if Ollama is missing, it prints winget install -e --id Ollama.Ollama and stops.

pwsh -File scripts\setup-ollama.ps1                 # llama3.1
pwsh -File scripts\setup-ollama.ps1 qwen2.5-coder   # or another model
pwsh -File scripts\setup-ollama.ps1 -StartOnly      # only start an installed Ollama

Windows CI checks that the script parses, the missing-Ollama paths and its refusal of bad arguments. The start, pull and check steps have not yet run on a Windows machine with Ollama. See Windows.

What the setup script does

The script is plain bash (set -euo pipefail), safe to run again, and prints each step. It is 55 lines; read it before you run it.

scripts/setup-ollama.sh, step by step
StepWhat happensIf it fails
1. Find OllamaLooks for ollama on your PATH. If it is missing, runs brew install ollama.Without Homebrew it stops and points you to ollama.com/download.
2. Start the serverAsks localhost:11434/api/tags. If nothing answers it starts ollama serve in the background (log: /tmp/ollama-serve.log) and waits up to 30 seconds.Stops and names the log file.
3. Pull the modelRuns ollama pull. The default, llama3.1, is about 5 GB the first time; later runs finish at once.Ollama’s own error is shown, for example an unknown model name.
4. Check it answersSends one tiny chat request to /v1/chat/completions, the same endpoint T.R.I.S.T.A.N. uses, and prints the reply.Stops and prints the error.
5. Check tool supportOffers a list_dir tool. If Ollama replies “does not support tools”, it prints a warning.Only a warning: the model still works for questions, not for coding.
6. SummaryPrints ollama list and, if the script started the server, how to stop it (pkill -f 'ollama serve').

What it does not do: it never touches T.R.I.S.T.A.N.’s settings, never sends anything off your machine except the model download, and never deletes models.

Choosing a model

T.R.I.S.T.A.N. edits files and runs commands through tool calls, so a coding task needs a model that supports them. Questions (and kids mode) work with any model.

Starting points
ModelGood for
llama3.1 (default)A solid all-rounder that handles tools.
qwen2.5-coderCoding tasks.
Any otherTry it. A model without tool support gets a clear message in the log and still answers plain questions.

Small models fumble tool calls more often than a cloud model, so expect simple edits to work better than long multi-step tasks. A short name such as qwen matches an installed qwen:7b.

How it works inside T.R.I.S.T.A.N.

  • One endpoint. It talks to Ollama’s OpenAI-compatible /v1/chat/completions, streaming, and reuses the same agent loop as Azure OpenAI.
  • Model discovery. GET /api/tags with a two-second timeout. A blank model means the first one in Ollama’s list, which is the one added or used most recently, so downloading another model can change which one T.R.I.S.T.A.N. uses. Choose a model in Configuration to pin it. This also decides which model the offline fallback and kids mode use. A short name such as llama3.1 matches llama3.1:latest.
  • This Mac only. The host must be localhost, 127.0.0.1 or ::1 over plain http. Anything else is refused before a prompt is sent.
  • Readable errors. Server not running, no model installed, model not found, model without tool support.

When the internet is down

If the Mac loses its connection, a mission on a cloud provider would just fail. Instead T.R.I.S.T.A.N. runs it on Ollama and tells you so. Nothing to switch on: it works as soon as Ollama is installed with a model.

  • You see it. An amber NO INTERNET · USING OLLAMA note appears in the header, and the mission log says “No internet connection. Falling back to the local model (Ollama) for this mission.”
  • Which providers fall back. Claude Code, Copilot, Amazon Bedrock and Azure OpenAI. Ollama itself and the demo provider are never rerouted.
  • How it knows. macOS reports whether the Mac has a route to the internet. A Wi-Fi network that is connected but has no real internet may not be noticed as offline.
  • If Ollama is off, the status shows STARTING OLLAMA and the log says it is working on the fallback. T.R.I.S.T.A.N. runs the bundled setup-ollama.sh --start-only, which starts the server and nothing else: no install and no download, because there is no internet to fetch them with. Then the mission runs.
  • If it cannot start, the mission stops with a clear message and nothing is sent anywhere. “Ollama is not installed” says to run scripts/setup-ollama.sh once you are online; “no model” says to run ollama pull llama3.1; otherwise it suggests ollama serve.
  • When it comes back, the note disappears and the next mission uses the provider you chose again. A mission that is already running is not moved: if its provider loses the connection it fails, and sending it again uses the fallback.
  • Kids safe mode already keeps questions on the Mac, so it behaves as before.

Because the local model has no internet either, expect shorter, simpler answers than a cloud model gives, and pick a model that supports tools if you want it to edit files (see above). The same --start-only flag works from a terminal: scripts/setup-ollama.sh --start-only exits 0 when Ollama is running, and 2 when it is not installed.

Troubleshooting

Symptoms and fixes
SymptomFix
“Ollama is not running”Run ollama serve, or open the Ollama app.
“No model installed”Run scripts/setup-ollama.sh or ollama pull llama3.1.
“Cannot use tools”Choose a tool-capable model in Configuration.
Kids mode says “ask a parent” every timeThe local model is not ready. Check ollama list and that the server is running.
The first answer is slowOllama loads the model into memory on first use.
