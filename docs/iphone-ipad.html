Guide

Take it with you.

Pair an iPhone or iPad with a QR code to approve from the couch, or run missions on the phone itself.

Two ways to use it

Remote

Control your Mac

The Mac does the real work with every provider. The phone shows the window, answers approvals with big buttons and haptics, starts missions (typed or dictated), switches provider and mode, controls Spotify and browses history.

Standalone

No Mac needed

The phone runs the same agent loop and talks straight to Azure OpenAI or Bedrock. The model can read, list and write files in one folder, but cannot run commands.

iPad

Side by side

On iPad the mission log and the code stream sit next to each other.

Pairing

  1. On the Mac open Configuration and switch REMOTE CONTROL on.
  2. Scan the QR code with the app, or copy the link and open it on the phone. You can also type the address and secret by hand.
  3. The Mac shows and logs every connection (“iPhone connected”) and lists connected devices.

How the link is secured

  • Off by default.
  • TLS 1.2 with a pre-shared key from Apple’s Network framework. The key is a random 256-bit secret from the QR code, held in the Keychain on both sides. A device with the wrong key is refused during the handshake, so nothing unauthenticated is ever read. NEW SECRET on the Mac locks out every paired device.
  • No Yolo from a phone. A phone cannot switch it on, and remote tasks are refused while the Mac is in Yolo mode. In kids mode a phone cannot change the mode either.
  • Folders from the Mac’s own list only, never an arbitrary path.
  • Limits: messages up to 1 MB, tasks up to 4,000 characters, and a handful of simultaneous connections.

Limits you should know

  • Approvals only arrive while the app is open in front. iOS pauses background apps and real push notifications need a server, which this project does not have. Keep T.R.I.S.T.A.N. open during a mission.
  • The Mac must be awake and reachable: the same Wi-Fi, or a VPN such as Tailscale (enter its address by hand).
  • Simulator only so far. It has run in the iOS simulator, not on a physical device or over real Wi-Fi. Camera scanning, dictation and haptics are untested.
  • All paired devices share one secret.
  • The remote controls the Mac’s active session. Approvals for a background session reach the phone only after you switch to it on the Mac.

Standalone mode

On the pairing screen choose USE WITHOUT A MAC, or switch in Settings (ON THIS DEVICE).

  • Providers: Azure OpenAI (endpoint, deployment, API key) and AWS Bedrock (region, model id, access key, secret and an optional session token). Keys live in this device’s Keychain, never in preferences.
  • Files, no shell: the model gets read_file, list_dir and write_file, confined to one folder. The default is Workspace, which appears in the Files app under On My iPhone > T.R.I.S.T.A.N.. Choose a folder in Files… adds another. iOS has no shell, so T.R.I.S.T.A.N. cannot run commands or tests here.
  • Approvals: the same approve, deny and always-allow card. In Auto mode writes inside the folder go ahead. Yolo does not exist on the device.
  • Key hygiene: use an AWS key that can only call Bedrock, and prefer temporary keys with a session token. Anyone who unlocks the phone can use the saved keys.

Run it in the simulator

scripts/ios-demo.sh                          # iPhone simulator against a demo Mac, no accounts needed
SIM="iPad Pro 11-inch (M4)" scripts/ios-demo.sh   # the iPad layout
MODE=standalone scripts/ios-demo.sh          # the on-device mode with a scripted model

The iOS project is generated from ios/project.yml with XcodeGen (cd ios && xcodegen generate). It compiles the shared code straight from Sources/Tristan/Shared and the portable core from Sources/TristanCore, so adding or removing a file in either needs the project regenerated (CI fails if the committed project is out of date). The project is generated without intermediate groups so the output does not depend on the checkout folder's name.
