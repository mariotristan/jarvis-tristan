Guide

Every model, one window.

T.R.I.S.T.A.N. drives five providers side by side. Here is how each one works, how to set it up, and what has been tested against the real thing.

At a glance

Where each provider stands
ProviderStatusHow it works
DEMOTested for realA scripted run with a fake approval, for trying the window without spending tokens.
CLAUDETested for realDrives the claude command line headlessly and turns its JSON events into log lines and code. Asks per action in Ask mode.
COPILOTPartly testedDrives the GitHub Copilot CLI. It cannot ask per action, so T.R.I.S.T.A.N. asks once and blocks risky commands. Two sessions were run live in Auto mode.
BEDROCKStand-in onlyT.R.I.S.T.A.N.’s own agent loop on Amazon Bedrock, through the AWS CLI so your usual sign-in works.
AZURETested for realT.R.I.S.T.A.N.’s own agent loop on an Azure OpenAI deployment, streaming tokens. Tested live with an API key.
OLLAMAStand-in onlyT.R.I.S.T.A.N.’s own agent loop on a model running on your Mac. Nothing leaves the machine. Tool format checked against a real model; no full mission recorded yet.

Claude Code runs its own agent loop, so T.R.I.S.T.A.N. only drives it and shows the output. Bedrock, Azure OpenAI, Copilot’s models and Ollama are models, not agents, so T.R.I.S.T.A.N. runs its own small agent loop for them. It can read files, list folders, write files and run commands, each one passing through your approval mode.

On Windows the same five providers run from the tristan terminal command (released in 0.6.1 as an installer and a zip). Their Windows plumbing is tested on a Windows CI runner with fake CLIs and stubs; none has run against a live account on Windows yet. Setup with tristan config and tristan secret is in the Windows guide.

Claude Code

  1. Install and sign in to the Claude Code CLI. T.R.I.S.T.A.N. looks for claude on your PATH, plus /opt/homebrew/bin and /usr/local/bin.
  2. Pick CLAUDE along the bottom of the window and choose a folder.
  3. Give it a task. In Ask mode every permission prompt comes back to you (see Approvals).

Actions you already allowed in your own Claude Code settings are not asked about again in Ask mode.

Azure OpenAI

Point T.R.I.S.T.A.N. at an Azure OpenAI deployment in Configuration: the endpoint (for example https://my-resource.openai.azure.com), the deployment name and the API version (default 2024-10-21). The deployment’s model must support tool calling; the GPT-4 and GPT-5 families do.

  • Credentials. Paste an API key and it is stored in your macOS Keychain. With no key, T.R.I.S.T.A.N. uses your Azure CLI login (az login) and an Entra ID token, so no secret is stored. The key path is tested live; the Azure CLI path is not yet.
  • Key safety. The key is only ever sent to an https endpoint on an Azure host. A typo such as http://… or a look-alike host is refused before anything is sent.
  • Errors. Wrong credentials, a missing deployment, rate limits and content-filter blocks produce readable messages in the mission log.

Amazon Bedrock

The BEDROCK provider calls aws bedrock-runtime converse through the AWS CLI, so your credentials, SSO and profiles work as in your terminal. Set the model id, region and an optional profile in Configuration (the gear button).

Not yet run against live AWS. Request signing matches Amazon’s published examples, the stream decoder matches the wire format, and the whole flow is covered by tests with a scripted model. If streaming fails it falls back to the CLI path automatically. Issue 1 tracks a live check.

GitHub Copilot

The COPILOT provider drives the GitHub Copilot CLI (npm install -g @github/copilot, then run copilot once to sign in). You can set a model in Configuration.

One honest limit. In headless mode the Copilot CLI cannot ask before each action. It only understands allow and deny lists, with denials always winning. So per-action approval and Always allow are not available for Copilot. That is a limit of the CLI, not a choice.

How the approval modes map onto the Copilot CLI
ModeWhat T.R.I.S.T.A.N. does
AskOne approval up front, then all tools are allowed except a deny list: rm, sudo, dd, chmod, chown, mv, kill, curl, wget, ssh, scp, git push, git reset and similar.
AutoOnly file writes and a short list of routine commands (git status, git diff, git log, git add, git commit, ls, cat, grep, swift build, swift test, npm test and a few more) are allowed. The deny list still applies.
YoloEverything is allowed, with no deny list.

Output is streamed as plain text because the CLI has no structured output mode yet. Two Copilot sessions ran live in Auto mode; Ask mode has only been tested with a stand-in process.

Ollama (local models)

Run a model on your own Mac through Ollama: no account, no key, no network. It uses the same agent loop as Azure, talking to Ollama’s OpenAI-compatible endpoint on localhost.

The Local models guide has the one-script setup, model advice and troubleshooting. Kids safe mode uses it too: see Kids safe mode.

It is also the offline fallback: with no internet, a mission on Claude Code, Copilot, Bedrock or Azure runs on Ollama, and T.R.I.S.T.A.N. starts Ollama if it is off. See When the internet is down.

Add your own provider

A provider turns a task into a stream of events. Implement one small protocol and add a case to ProviderKind:

protocol AgentProvider: Sendable {
    func run(task: String, workingDirectory: URL, approve: @escaping Approver) -> AsyncStream<AgentEvent>
}

Events are status, log, code, done and failed. A provider asks for permission by calling approve(...), which waits until you tap Approve or Deny. For a model that speaks the OpenAI chat format, reuse AgentLoop and AzureBackend, as the Ollama provider does in about 125 lines. The README has the full steps.
