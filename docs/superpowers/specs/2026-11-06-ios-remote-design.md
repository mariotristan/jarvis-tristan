# Tristan for iPhone and iPad: design

## Intent
An iPhone cannot run the Claude Code, Copilot or AWS command-line tools and has no shell or project folders. The most useful iOS version is therefore a **remote for the Mac**: you start missions, watch the HUD, hear about and answer approval prompts, and control Spotify from your phone or iPad, while the Mac does the real work with every provider already built. A **standalone mode** (the phone talks straight to Azure OpenAI and Bedrock and edits files in a folder picked in the Files app) follows on the same shared code.

Decided by the user: remote first, then standalone; iPhone and iPad from the start.

## Goals
- Approve or deny actions from the phone, with large buttons and haptics.
- Same look as the Mac HUD (reactor, mission log, code stream), laid out for a phone, and side by side on iPad.
- Pair once; reconnect automatically on the same network.
- Safe by default: nothing is reachable until the user enables it on the Mac and pairs a device.

## Non-goals (for now)
- Background delivery. iOS suspends sockets when the app is not in front, so approvals only arrive while the app is open. Push notifications need a server (APNs) and are out of scope; Live Activities are a later idea.
- Internet access without a VPN. Bonjour discovery is local-network only. Users can enter a host manually, for example a Tailscale address.
- Running shell commands on the phone.

## Architecture
```
iPhone / iPad app  ──TLS-PSK, length-prefixed JSON──▶  Tristan on the Mac (RemoteServer)
 RemoteClient + HUD UI                                    observes and drives the Session
```
- **Transport:** TCP with TLS 1.2 and a pre-shared-key cipher suite (`TLS_PSK_WITH_AES_128_GCM_SHA256`) from Apple's Network framework. A spike confirmed a client with the wrong key is rejected during the handshake (`bad MAC`). The key is a random 256-bit secret, so there is no password to guess.
- **Framing:** a 4-byte big-endian length followed by a JSON message, 1 MB maximum.
- **Discovery:** Bonjour `_tristan._tcp`. Manual host and port entry is also supported.
- **Shared code:** `Sources/Tristan/Shared/` (protocol, framing, transport, client, theme, models) compiles for macOS and iOS. The iOS project (`ios/`, generated by XcodeGen) includes those files directly.

## Pairing
The Mac (Configuration, Remote) generates the secret, stores it in the Keychain, and shows it as a QR code and a copyable link: `tristan://pair?host=…&port=…&secret=…`. The phone scans the QR code, opens the link, or takes the values by hand, and stores the secret in its own Keychain. **Regenerate** on the Mac invalidates every paired device. All devices share one secret (my call, for simplicity; per-device keys are a possible later change).

## Security model
- Remote control is **off by default** and must be switched on on the Mac.
- The Mac shows and announces every connection ("iPhone connected") and lists connected devices.
- A remote device **cannot enable `YOLO`**, and remote tasks are **refused while the Mac is in `YOLO`** (an unattended remote must never mean unsupervised).
- A remote device can only pick a working folder from an **allow-list** (the Mac's current folder plus recent mission folders), never an arbitrary path.
- Limits: 1 MB per message, a small number of simultaneous connections, task text capped at 4,000 characters.
- Approvals are answered by the device that sees them first; the Mac UI keeps working in parallel.

## Protocol (version 1)
Client to server: `hello`, `submit`, `cancel`, `approval(id, allow|deny|always)`, `setProvider`, `setMode`, `setFolder(path)`, `music(command)`, `requestHistory`, `ping`.
Server to client: `welcome(snapshot)`, `snapshot`, `log`, `code` (ordered deltas), `approval`, `approvalCleared`, `history`, `error`, `pong`.
A new mission gets a new `missionID`; on connect the server replays the current log and code.

## Phases
1. **Remote core (this change):** shared protocol, framing, transport and client; the Mac `RemoteServer` with settings and pairing; end-to-end tests over loopback.
2. **iOS app:** pairing, mission screen, approvals, history, music, dictation; iPhone and iPad layouts; run in the simulator.
3. **Standalone mode (later):** Azure OpenAI and Bedrock directly from the phone using the existing agent loop, with file tools limited to a Files-app folder and no shell.

## Testing
- Unit tests for framing, protocol round trips and the security rules.
- End-to-end tests on loopback: a real `RemoteClient` against a real `RemoteServer` driving a demo mission, including approvals, a wrong key, the YOLO guard and the folder allow-list.
- iOS: build and run in the simulator, with screenshots. Not tested on a physical device or against a real Mac over Wi-Fi.

## Status
Phases 1 and 2 are built and run in the simulator (iPhone and iPad), with 17 remote tests on the Mac side and 3 on iOS. Phase 3 (standalone) is not started. Not yet done: running on a physical device, camera QR scanning, dictation and haptics (the simulator has none of them), Bonjour discovery (the Mac advertises `_tristan._tcp` already, the app does not browse for it yet), and per-device keys.
